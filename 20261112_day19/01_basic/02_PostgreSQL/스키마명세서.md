# 실습 2A · 기본필수 ERD·스키마 명세서

**구축할 DB: `day19_build_b`** · Schema: `public`
관계는 모든 수준에서 동일합니다. 테이블 수가 아니라 DDL 작성 범위와 파일 책임을 단계별로 늘립니다.

## ERD
<div class="erd"><div class="entity"><h3>categories · 분류</h3><p><b>PK</b> id : BIGINT / ALWAYS IDENTITY<br>name : VARCHAR(30) / NOT NULL / UNIQUE</p><p>이름 길이 1~30</p></div><div class="link">1 ───── 0..N<br><small>id ← category_id<br>부모 삭제 RESTRICT</small></div><div class="entity"><h3>knowledge · 지식</h3><p><b>PK</b> id : BIGINT / ALWAYS IDENTITY<br>title : VARCHAR(80) / NOT NULL<br>content : TEXT / NOT NULL<br><b>FK</b> category_id : BIGINT / NOT NULL</p><p>제목 1~80 · 본문 1~2000</p></div></div>

분류 하나는 지식이 0개 이상일 수 있습니다. 지식 하나는 **정확히 하나의 기존 분류**를 참조합니다.
자식이 참조 중인 부모 분류는 삭제할 수 없으며, 지식 삭제가 부모 분류를 자동으로 삭제하지 않습니다.

```text
categories.id [1] <──────── [0..N] knowledge.category_id
                     FK + NOT NULL, ON DELETE RESTRICT
```

## categories 명세
| 열 | 자료형 | NULL | 키·생성 규칙 | 추가 규칙 |
|---|---|---|---|---|
| id | BIGINT | 불가 | PRIMARY KEY · GENERATED ALWAYS AS IDENTITY | 직접 지정하지 않고 DB가 발급 |
| name | VARCHAR(30) | 불가 | UNIQUE | categories_name_length: char_length(name) 1~30 |

## knowledge 명세
| 열 | 자료형 | NULL | 키·생성 규칙 | 추가 규칙 |
|---|---|---|---|---|
| id | BIGINT | 불가 | PRIMARY KEY · GENERATED ALWAYS AS IDENTITY | 제목과 별개인 식별자 |
| title | VARCHAR(80) | 불가 | 중복 허용 | knowledge_title_length: 길이 1~80 |
| content | TEXT | 불가 | 없음 | knowledge_content_length: 길이 1~2000 |
| category_id | BIGINT | 불가 | FK → public.categories(id) | knowledge_category_fk · ON DELETE RESTRICT |

NOT NULL은 NULL을 막고, 길이 CHECK는 빈 문자열을 막습니다. 공백만 있는 문자열 거부·trim·제목 UNIQUE는 추가하지 않습니다.
API 문자열 category를 자동으로 DB에 동기화하지 않습니다. 이 실습에서는 위 두 DB 테이블만 구축합니다.

## 구축 완료 확인
`A_구축/check_structure.sql`은 제공된 읽기 전용 점검입니다. 다음을 실제 catalog 결과로 대조합니다.
- categories: id·name 2열, knowledge: id·title·content·category_id 4열
- id 두 개: BIGINT(정보 스키마 표기 bigint), is_identity=YES, identity_generation=ALWAYS
- 모든 열 is_nullable=NO, name 최대30·title 최대80·content text
- 각 PK, name UNIQUE, 지정 CHECK 3개, FK와 RESTRICT

`A_구축/check_insert.sql`은 정상 입력이 연결되는지 확인한 뒤 ROLLBACK하는 제공 점검입니다.
비어 있는 구축 DB 기준 정상 JOIN 1행, 취소 뒤 knowledge_count=0입니다. ID 발급 번호가 증가해도 실패로 보지 않습니다.
**오류가 난 상태에서는 ROLLBACK을 따로 실행하고 원인을 고칩니다.** 이미 성공한 부모 CREATE를 다시 실행하지 않습니다.
DBML은 보조 설계 파일이며 PostgreSQL에서 실행하는 SQL이 아닙니다. 외부 도구 가입은 필요 없습니다.
