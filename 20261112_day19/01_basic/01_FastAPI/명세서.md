# 실습 1 · 기본필수 API 명세서

## 목표와 범위
명세의 요청에 대해 **예상 응답과 실제 JSON 저장 결과**가 나오도록 구현합니다.
저장소는 이 프로젝트의 `data/knowledge.json`입니다. **PostgreSQL·ORM·Migration은 사용하지 않습니다.**
새 주제를 정하지 않고 제공된 지식 데이터로 결과를 대조합니다. 오후 자료는 포함하지 않습니다.

## 1. 실행 위치와 구현 파일
VS Code에서 이 `01_FastAPI` 폴더를 엽니다. 기존에 정상 실행되는 Python 가상환경을 선택합니다.

```powershell
python -m pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

브라우저에서 `http://127.0.0.1:8000/docs`를 엽니다. 다른 실습 서버는 Ctrl+C로 종료합니다.
이 폴더에 필요한 환경이 이미 있으면 불필요하게 재설치하지 않습니다. `.venv` 활성화가 막히면 [공통 안내](../../공통/환경_실행안내.md)를 참고합니다.

`main.py`의 6개 TODO만 완성합니다. 입력 모델·파일 보조 함수는 제공됩니다.

수강생용 TODO의 `NotImplementedError`는 의도적인 미완성 표시입니다. 서버와 `/docs`가 열려도 모든 기능이 완성된 것은 아닙니다.
**정답 JSON을 상수로 반환하지 마세요.** 저장 파일을 읽고 실제 대상만 변경해야 합니다.

## 2. 입력·응답 계약
| 필드 | 요청 자료형 | 필수 | 규칙 |
|---|---|---|---|
| title | 문자열 | 예 | 1~80자 |
| content | 문자열 | 예 | 1~2000자 |
| category | 문자열 | 예 | 1~30자, 특정 목록으로 제한하지 않음 |
| id | 서버 응답의 정수 | 요청에서 작성하지 않음 | 서버가 next_id로 생성 |

POST와 PUT은 같은 입력 모델을 씁니다. **PUT도 세 필드를 모두 보내며 ID는 유지**합니다. 없는 ID에 PUT하면 새 항목을 만들지 않습니다.
제목은 중복될 수 있습니다. 공백 자동 제거·공백만 입력 거부·추가 필드 금지는 이번 공통 계약에 넣지 않습니다.
현재 제공 모델은 Pydantic 기본 동작을 사용하므로 추가 입력 필드는 무시합니다. 일반 요청에는 위 세 필드만 보내세요.
응답 항목은 `id`, `title`, `content`, `category` 네 필드입니다. JSON 객체 키의 표시 순서는 비교하지 않습니다.

| Method | Path | 입력 | 성공 | 실패 |
|---|---|---|---|---|
| GET | /health | 없음 | 200 · {"status":"ok"} | 파일·DB·모델 전체 준비 상태를 뜻하지 않음 |
| GET | /api/knowledge | 없음 | 200 · id 오름차순 배열 | 빈 목록도 200·[] |
| GET | /api/knowledge/{knowledge_id} | 정수 Path | 200 · 지식 하나 | 없는 정수 404 / 정수 아님 422 |
| POST | /api/knowledge | JSON Body 세 필드 | 201 · 생성된 지식 | 잘못된 Body 422 |
| PUT | /api/knowledge/{knowledge_id} | 정수 Path + Body 세 필드 | 200 · 수정된 지식 | 정상 Body+없는 ID 404 / 잘못된 입력 422 |
| DELETE | /api/knowledge/{knowledge_id} | 정수 Path | 204 · 본문 없음 | 없는 정수 404 |

없는 지식의 오류 본문은 **`{"detail":"Knowledge not found"}`**로 통일합니다.
422는 FastAPI 기본 오류 형식을 유지합니다. 상태와 `detail`의 오류 위치(`loc`)·규칙을 확인하며 영어 문구 전체 일치는 요구하지 않습니다.

## 3. 데이터 변경 규칙
생성은 새 ID를 발급하고 항목 수와 next_id를 각각 1 늘립니다. 수정은 ID·항목 수·next_id를 바꾸지 않습니다.
삭제는 해당 항목 하나만 제거하며 next_id를 줄이지 않습니다. 읽기·404·422는 저장 내용을 바꾸지 않습니다.
서버 시작 때 seed를 자동 복사하지 않습니다. 수정·삭제 결과는 서버 재시작 후에도 유지되어야 합니다.
기본 저장 파일 형식은 `{"next_id": 4, "entries": [...]}`입니다. API 응답에는 next_id를 노출하지 않습니다.

## 4. 수준별 추가 계약
기본필수에는 분류 Query 구현을 요구하지 않습니다. 다섯 CRUD와 저장·오류 처리를 먼저 완성합니다. 자동 테스트 작성도 요구하지 않습니다.

## 5. 완료 기준
[예상 결과](예상결과.md)의 순서대로 응답·실제 저장·재시작을 확인합니다.
[ ] 목록·상세  [ ] 생성  [ ] PUT  [ ] 삭제  [ ] 404·422  [ ] 변경 내용 저장 유지

자동 확인을 실행하려면 다음 명령을 사용합니다. **원본 작업 파일은 건드리지 않고 임시 복사본을 검사**합니다.
검사 도구를 작성하는 것은 기본필수·응용의 과제가 아닙니다.

```powershell
python -m pip install -r requirements-check.txt
python check_api.py
```

화면에서 수동으로 확인해도 공통 완료입니다. 자동 확인은 API 응답과 파일 상태를 검사하지만 실제 서버 종료·재시작은 명세의 수동 단계로도 확인하세요.
단일 PC·단일 서버 프로세스용이며 외부 공개·인증·운영 배포는 범위에 없습니다.
