# 실습 1 · 기본필수 예상 결과

## S0: 시작 상태
배포된 `knowledge.json`은 **지식 3개·next_id=4**입니다. 이미 실습했다면 서버를 종료하고 `python reset_data.py --confirm`으로 **이 폴더의 JSON만** 초기화할 수 있습니다.
초기화는 명시적 복습 작업이며 서버 재시작과 다릅니다. 기존 작업 파일은 자동 백업됩니다.

### K01. GET /api/knowledge → 200
```json
[
  {
    "id": 1,
    "title": "실습 파일 보관",
    "content": "실습 파일은 개인 폴더에 보관합니다.",
    "category": "learning"
  },
  {
    "id": 2,
    "title": "서버 실행",
    "content": "프로젝트 폴더에서 서버를 실행합니다.",
    "category": "environment"
  },
  {
    "id": 3,
    "title": "질문 작성",
    "content": "오류 메시지와 시도한 작업을 함께 적습니다.",
    "category": "learning"
  }
]
```
### K02. GET /api/knowledge/2 → 200
```json
{
  "id": 2,
  "title": "서버 실행",
  "content": "프로젝트 폴더에서 서버를 실행합니다.",
  "category": "environment"
}
```
### K03. 없는 ID와 잘못된 입력
초기 ID 999999는 없습니다. PUT은 `requests/PUT_valid.json`의 정상 Body로 검사합니다.

| 요청 | 상태 | 비교 기준 | 저장 변화 |
|---|---|---|---|
| GET /api/knowledge/999999 | 404 | {"detail":"Knowledge not found"} | 없음 |
| PUT /api/knowledge/999999 + 정상 Body | 404 | 동일한 detail | 없음 |
| DELETE /api/knowledge/999999 | 404 | 동일한 detail | 없음 |
| GET /api/knowledge/foo | 422 | loc에 path·knowledge_id | 없음 |
| POST + requests/POST_empty_content.json | 422 | loc에 body·content, 최소 길이 위반 | 없음 |
| PUT /api/knowledge/2 + requests/PUT_missing_fields.json | 422 | title·category 필수 값 누락 | 없음 |

[ ] 정상 읽기 결과  [ ] 404  [ ] 422  [ ] 파일 불변

## 변경 시나리오: K05 → K06 → K07 순서
다음 작업을 **한 번씩** 수행합니다. POST를 반복 클릭하면 다른 지식이 추가되므로 결과 개수가 달라집니다.
서버가 돌려준 ID를 `created_id`로 기억합니다. 아래 숫자 4는 S0에서 정상 생성 1회일 때만의 예시입니다.

### K05. POST /api/knowledge
요청 Body (`requests/POST_valid.json`):
```json
{
  "title": "보충 학습",
  "content": "복습 자료는 개인 폴더에서 확인합니다.",
  "category": "learning"
}
```
예상: **201**. 초기화 직후 예시:
```json
{
  "id": 4,
  "title": "보충 학습",
  "content": "복습 자료는 개인 폴더에서 확인합니다.",
  "category": "learning"
}
```
목록은 4개이며 기존 1~3은 그대로이고, `data/knowledge.json`에 새 항목과 다음 ID가 함께 저장됩니다.
일반 검증은 `created_id`가 기존 ID와 다르고, 저장된 id와 응답 id가 같으며, next_id가 이전보다 1 증가하는지 확인합니다.

### K06. PUT /api/knowledge/{created_id}
요청 Body (`requests/PUT_valid.json`):
```json
{
  "title": "보충 학습",
  "content": "복습 자료와 예제 코드를 함께 확인합니다.",
  "category": "learning"
}
```
예상: **200**, 같은 ID·같은 제목·같은 분류, 바뀐 본문. 초기화 직후 예시:
```json
{
  "id": 4,
  "title": "보충 학습",
  "content": "복습 자료와 예제 코드를 함께 확인합니다.",
  "category": "learning"
}
```
목록 4개·다음 ID 유지. **Ctrl+C로 서버를 종료하고 같은 명령으로 재실행한 뒤 같은 ID를 GET하면 수정 내용이 유지**되어야 합니다.
[ ] PUT 응답  [ ] 파일의 본문  [ ] 재시작 후 본문

### K07. DELETE /api/knowledge/{created_id}
예상: **204**, 응답 본문 길이 0. 문자열 `null`, `{}`, 삭제 메시지를 반환하지 않습니다.
같은 ID를 GET하면 404·`{"detail":"Knowledge not found"}`입니다. 재시작한 뒤에도 404여야 합니다.
최종 목록은 다시 **S0의 기존 세 항목**이며, next_id는 초기화하지 않습니다(처음 한 번 수행했다면 5).
[ ] 빈 204  [ ] 삭제 후404  [ ] 기존 세 항목 보존  [ ] 재시작 후 삭제 유지

## 예상값 비교 규칙

JSON 객체 키 순서와 공백·들여쓰기는 비교하지 않습니다. 목록 항목의 순서와 값은 비교합니다.
`expected/*_example.json`의 id 4는 **S0 기준 예시**이지 모든 실행에 고정해야 하는 정답이 아닙니다.
422의 영어 오류 메시지 전체나 헤더 순서는 버전별로 달라질 수 있으므로 계약의 필드·상태·규칙으로 판단합니다.
