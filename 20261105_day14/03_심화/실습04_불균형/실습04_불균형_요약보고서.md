## 1. Executive Summary

본 실습의 목적은 train이 circle 120·square 40·triangle 20(6:2:1)으로 불균형할 때, **손실 가중치(Class weight)**와 **재추출(Sampler)**을 각각 **독립 후보**로 두고 기준선과 같은 조건에서 비교하는 법을 익히는 것이다. 이를 위해 TODO D04에서 `methods=["none","weight","sampler"]`로 세 후보를 나열하였다(동시 적용 없음).

**실제 실행 결과 기준**, 세 후보 모두 valid Accuracy·Macro F1·triangle Recall이 **1.0**이었다. best epoch(8)의 valid loss는 none **0.012641**, weight **0.006550**, sampler **0.006475**였다. 1 epoch 직후 valid Macro F1은 none 0.956, weight 0.978, sampler 1.000으로 보정 후보가 더 빨리 올라갔다. Sampler는 8 epoch 동안 triangle을 487회 뽑았다(기준선 160회).

**두 방법 비교·과적합 해석 요약 (2.4절, 3.5~3.6절 상세):**
- **같은 조건 비교:** weight와 sampler는 seed 14·8 epoch·head 전략·batch 16·학습률·BN 정책이 모두 같고 balance 하나만 다르다.
- **minority Recall:** 세 후보 모두 triangle Recall 1.0이라 Recall로는 구분되지 않는다. 대신 triangle valid 손실이 none 0.0178 → weight 0.0068 / sampler 0.0066으로 줄었고, 가장 낮은 triangle 정답 확률도 0.762 → 0.882 / 0.895로 올라갔다. 그 대가로 circle valid 손실은 0.0039 → 0.0053 / 0.0084로 늘었다.
- **과적합 징후:** 8 epoch 안에서는 관찰되지 않았다. 세 후보 모두 valid loss 최소가 마지막 epoch 8이고, 최종 모델의 valid−train 비가중 손실 차이는 none 0.0063, weight 0.0022, sampler 0.0011로 작다. triangle 20장을 평균 24회 반복한 sampler도 triangle train 0.0052 / valid 0.0066으로 차이가 작았다.

**README 질문 요약 (2.3절 상세):**
- **Accuracy는 높고 minority Recall은 0일 수 있는가:** 있다. valid가 train처럼 6:2:1이면 triangle을 전부 틀려도 Accuracy는 최대 88.9%다. 이번 valid는 30/30/30 균형이라 그 경우 Accuracy가 66.7% 이하로 드러난다.
- **weight와 sampler가 바꾸는 것:** weight는 같은 데이터에서 **손실 기여도**를 바꾸고(0.3 / 0.9 / 1.8배), sampler는 **학습에 들어가는 표본 구성**을 바꾼다(epoch당 약 60/60/60, 복원 추출).

**최종 판단:** 불균형 대응 후보 비교의 실습 완료 조건을 충족했다(PASS). 세 후보 모두 valid 1.0으로 포화되어 **어느 방법이 더 좋은지는 판정하지 않는다**. loss 차이와 초기 수렴 속도는 단일 seed 관찰값이다.

### 2.3 README 질문 답변

#### Q1. Accuracy는 높고 minority Recall은 0일 수 있는가?

**있다.** Accuracy는 전체 표본 중 정답 비율이라 다수 클래스가 대부분을 차지하면 소수 클래스의 실패가 거의 반영되지 않는다. 예를 들어 valid가 train과 같은 비율(circle 120·square 40·triangle 20)이고 모델이 triangle을 모두 다른 클래스로 예측하되 나머지는 모두 맞히면, Accuracy = 160/180 = **88.9%**, triangle Recall = **0**, Macro F1은 triangle F1이 0이라 크게 떨어진다. 그래서 이 프로젝트는 주 지표를 Macro F1로 두고 `triangle_recall`을 별도로 기록한다. 이번 valid는 30/30/30 균형이라 같은 실패는 Accuracy 66.7% 이하로 바로 드러난다. 실측에서는 세 후보 모두 triangle Recall 1.0이라 이런 실패가 관찰되지 않았다.

#### Q2. weight와 sampler는 무엇을 각각 바꾸는가?

| 구분 | Class weight | WeightedRandomSampler |
|:--|:--|:--|
| 바꾸는 것 | **손실 함수**: 클래스별 손실 기여도 | **데이터 공급**: epoch에 뽑히는 표본 구성 |
| 이 실습 값 | 역빈도 정규화 [circle 0.3, square 0.9, triangle 1.8] | 표본 가중치 1/count, 180장 복원 추출 |
| 학습 데이터 | 매 epoch 120/40/20 그대로 | epoch당 약 60/60/60 (실측 1 epoch: 57/60/63) |
| 부작용 | train_objective가 가중 손실이라 valid_loss와 같은 척도가 아님 | 같은 triangle 이미지가 반복 등장 → 과적합 위험, circle 일부는 덜 보게 됨 |
| valid | 비가중 손실로 동일 평가 | 재추출하지 않음 (원래 분포) |

8 epoch 누적 draw 수(실측): sampler circle 484·square 469·triangle 487, none은 960·320·160이다. triangle 20장이 sampler에서는 이미지당 평균 약 24회, 기준선에서는 8회 학습에 쓰였다.

### 2.4 비교 포인트: 두 방법을 같은 seed·epoch에서 비교했는가

두 방법의 차이를 balance 설정 하나로만 설명하려면, 나머지 조건이 모두 같아야 한다. `experiment()` 호출은 `balance=method` 외에 모두 같은 기본값을 쓴다.

| 조건 | none | weight | sampler | 같은가 |
|:--|:--|:--|:--|:--:|
| seed (모델 초기화·셔플/추출 Generator) | 14 | 14 | 14 | 같음 |
| epoch 예산 | 8 | 8 | 8 | 같음 |
| epoch당 학습 표본 수 | 180 | 180 | 180 (복원 추출) | 같음 |
| 학습 범위 | head (771개) | head (771개) | head (771개) | 같음 |
| optimizer·학습률 | AdamW, head_lr 0.01, wd 1e-4 | 동일 | 동일 | 같음 |
| BN 정책 | running 통계 고정 | 동일 | 동일 | 같음 |
| valid 평가 | 비가중 손실, 90장 원래 분포 | 동일 | 동일 | 같음 |
| **다른 점** | 보정 없음 | **손실에 클래스 가중치** | **표본 추출 확률** | — |

비교할 때 주의할 점은 다음과 같다.

- **같은 척도끼리만 비교한다.** weight의 `train_objective`는 가중 손실이라 none·sampler의 train 손실이나 valid_loss와 척도가 다르다. 그래서 train·valid 비교(3.6절)는 최종 모델로 train 180장을 **비가중 손실**로 다시 평가한 값으로 했다.
- **seed가 같아도 배치 순서는 같지 않다.** sampler는 같은 Generator를 셔플 대신 복원 추출에 쓰므로 epoch마다 들어가는 이미지 자체가 다르다. 따라서 차이에는 "보정 효과"와 "배치 구성 차이"가 섞여 있다.
- **단일 seed·단일 실행이다.** 아래 손실 차이는 우열의 근거가 아니라 관찰값이다.

### 3.5 minority Recall 해석 (`outputs/overfit_check.csv`, 보조 측정)

세 후보 모두 triangle Recall이 1.0이라 **Recall만으로는 두 방법의 차이가 보이지 않는다**. Recall은 확률이 가장 큰 클래스가 맞았는지만 세므로, "얼마나 확실하게 맞혔는가"는 클래스별 손실과 최소 정답 확률로 보았다.

| 클래스 (train 장수) | 지표 (valid) | none | weight | sampler |
|:--|:--|--:|--:|--:|
| triangle (20, 소수) | Recall | 1.0 | 1.0 | 1.0 |
| | 평균 손실 | 0.0178 | 0.0068 | 0.0066 |
| | 최소 정답 확률 | 0.762 | 0.882 | 0.895 |
| square (40) | 평균 손실 | 0.0163 | 0.0075 | 0.0045 |
| | 최소 정답 확률 | 0.783 | 0.907 | 0.941 |
| circle (120, 다수) | 평균 손실 | 0.0039 | 0.0053 | 0.0084 |
| | 최소 정답 확률 | 0.931 | 0.895 | 0.839 |

- **관찰:** 두 보정 방법 모두 소수 클래스(triangle·square)의 손실을 기준선의 절반 이하로 줄이고 가장 애매한 표본의 정답 확률을 올렸다. 반대로 다수 클래스 circle의 손실은 늘고 최소 확률은 내려갔다. sampler 쪽이 소수 클래스 개선과 circle 악화가 둘 다 더 크다.
- **해석:** 보정은 결정 경계를 소수 클래스 쪽에서 다수 클래스 쪽으로 옮기는 **교환(trade-off)**이다. 이번에는 모든 클래스가 여전히 정답이라 Recall이 바뀌지 않았지만, 더 어려운 데이터에서는 triangle Recall이 오르는 대신 circle Recall이 내려갈 수 있다.
- **valid loss 해석:** 전체 valid loss(none 0.0126 → 0.0066/0.0065)가 줄어든 이유는 valid가 30/30/30 균형이라 소수 클래스 손실 감소가 그대로 평균에 반영되기 때문이다. 운영 분포가 train처럼 6:2:1이면 circle 손실 증가의 비중이 커져 결과가 달라질 수 있다.
- **초기 수렴:** 1 epoch 뒤 valid Macro F1이 none 0.956, weight 0.978, sampler 1.000이었다(3.3절). 보정이 소수 클래스를 더 빨리 맞히게 한 관찰이다.

### 3.6 과적합 징후 해석

과적합은 **train 성능은 계속 좋아지는데 valid 성능은 멈추거나 나빠지는 현상**이다. 다음 세 가지로 점검했다.

**(1) valid loss가 끝에서 다시 오르는가 (`<method>_history.csv`)**

| 후보 | valid loss 최소 epoch | epoch 1 → 8 valid loss | 중간 상승 구간 |
|:--|--:|:--|:--|
| none | 8 | 0.1587 → 0.0126 | 없음 (매 epoch 감소) |
| weight | 8 | 0.0825 → 0.0066 | 없음 (매 epoch 감소) |
| sampler | 8 | 0.0590 → 0.0065 | epoch 4: 0.0111 → 0.0198 (F1 0.989), epoch 5부터 다시 감소 |

세 후보 모두 best epoch가 마지막 epoch 8이다. 과적합이면 best epoch가 앞쪽에 오고 뒤로 갈수록 valid loss가 올라야 하는데, 그런 모양은 없었다. sampler의 epoch 4 상승은 한 번뿐이고 다음 epoch에 회복되어, 복원 추출로 epoch마다 배치 구성이 바뀌는 데서 오는 흔들림으로 보인다(가설). sampler의 train_objective도 epoch 6~7에 0.0054 → 0.0078 → 0.0096으로 올랐는데, 같은 기간 valid loss는 계속 내려갔으므로 과적합 신호가 아니라 추출 표본 변화로 해석한다.

**(2) 최종 모델의 train·valid 손실 차이 (비가중, `outputs/overfit_check.csv`)**

| 후보 | train 손실 | valid 손실 | 차이 (valid − train) | train / valid Macro F1 |
|:--|--:|--:|--:|:--|
| none | 0.0064 | 0.0126 | 0.0063 | 1.0 / 1.0 |
| weight | 0.0043 | 0.0066 | 0.0022 | 1.0 / 1.0 |
| sampler | 0.0054 | 0.0065 | 0.0011 | 1.0 / 1.0 |

차이는 세 후보 모두 0.01 미만으로 작고, 보정 후보가 기준선보다 오히려 작다.

**(3) 반복 학습된 triangle에서 차이가 벌어졌는가**

| 후보 | triangle 1장당 학습 횟수 (8 epoch) | triangle train 손실 | triangle valid 손실 |
|:--|--:|--:|--:|
| none | 8 | 0.0219 | 0.0178 |
| weight | 8 (손실 1.8배 반영) | 0.0060 | 0.0068 |
| sampler | 약 24 | 0.0052 | 0.0066 |

sampler는 같은 triangle 이미지를 기준선의 약 3배 보았지만 triangle의 train·valid 손실 차이는 0.0014에 그쳤다. 외워서 train에서만 잘 맞히는 모양이 아니다.

**결론과 한계:** 이번 8 epoch·Head만 학습(771개) 조건에서는 **두 방법 모두 과적합 징후가 관찰되지 않았다.** 학습 파라미터가 적고, 합성 도형이라 train·valid의 모양 차이가 작은 것이 이유로 보인다(가설). 다만 epoch을 늘리거나 partial·full로 Backbone을 열면 반복 표본이 많은 sampler에서 먼저 차이가 벌어질 수 있으므로, 같은 점검(best epoch 위치, 비가중 train·valid 차이, 소수 클래스 손실 차이)을 다시 해야 한다.
